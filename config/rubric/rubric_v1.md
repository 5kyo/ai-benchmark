# LLM 채점 루브릭 v1 (축 A·B·C·D의 LLM 지표)

> Claude Code / Codex CLI가 이 루브릭으로 채점한다. 규칙 지표(A·B·D 일부)는 크롤러가 자동 계산하므로 여기서는 다루지 않는다.
> 각 지표는 0~100 정수로 채점하고, 1~2줄 근거(evidence)를 함께 낸다. **홈페이지 원문에 있는 내용만으로** 판단하고, 원문이 비었거나 봇 차단 페이지면 낮게 준다.

## 축 A — 접근성 (에이전트가 정보에 도달·수집)
- **agent_findability**: AI 에이전트가 회사·제품의 핵심 정보를 몇 번의 탐색으로 찾을 수 있는가. 핵심 소개가 전면·상단에 노출될수록 높다.
- **content_extractability**: 본문이 방해 요소(과도한 팝업, 이미지 안에 박힌 텍스트, 인터랙션 의존) 없이 순수 텍스트로 깔끔히 추출되는가.

## 축 B — 구조화 (기계가 구조를 이해)
- **logical_organization**: 콘텐츠가 논리적 순서와 명확한 제목 위계로 조직돼 기계가 정보 흐름을 파악하기 쉬운가.
- **info_scannability**: 핵심 정보가 목록·표·구획 등으로 구조화돼 빠르게 스캔·파싱되는가. 긴 문단 나열일수록 낮다.

## 축 C — 콘텐츠 품질/완성도
- **clarity**: 이 회사가 무엇을 하는지 홈페이지만으로 명확한가.
- **product_depth**: 제품/서비스 설명이 충분히 구체적인가.
- **key_info_present**: 토크노믹스·백서·팀·컨택 등 핵심 정보가 있는가.
- **freshness_clarity**: 최신성 있고 모호/과장 없는 서술인가.

## 축 D — 기술 품질 (정성적 신뢰 신호)
- **technical_depth**: 문서·API·SDK·보안·인증·규제 준수·성능 등 기술적 깊이와 신뢰 신호가 콘텐츠에 드러나는가.
- **content_polish**: 서술·번역·용어의 일관성과 전문성. 오탈자·어색한 번역·근거 없는 과장이 없을수록 높다.
